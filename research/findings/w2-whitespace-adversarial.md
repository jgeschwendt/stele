# W2 Whitespace — Adversarial attack on the "no tool does both" claim

**Claim under attack:** _As of 2026-07, no tool BOTH generates hierarchical agent-facing codebase docs committed into the repo AND drift-checks them against code in CI._

**Verdict: UPHELD** under a strict reading of all four conjuncts (hierarchical · agent-facing · committed · CI drift-_check_). Two tools (RepoAgent, Loki Mode/`loki docs`) come mechanically close and would **plausibly refute under a loose reading** where "drift-check" is relaxed to "auto-regenerate on change" and "agent-facing" is dropped. The two halves of the claim each exist as separate, mature tools; nobody ships them fused for the agent-facing hierarchical-router use case. Refutation attempt failed, but the whitespace is _thin_ — combining an existing generator (hcc) with an existing drift-linter (agents-lint) or the generic `regenerate + git diff --exit-code` CI pattern is trivial and clearly imminent.

Date of investigation: 2026-07-19. All sources web, dated where available.

---

## The conjunctive test

A refuting tool must satisfy **all** of:

1. **Generate hierarchy** — root + nested/per-directory docs, not a single flat file or in-code docstrings.
2. **Agent-facing** — docs meant to be _read by_ coding agents (AGENTS.md / CLAUDE.md router style), not human reference docs merely _generated by_ agents.
3. **Committed to repo** — files land in the repo tree, not a hosted wiki.
4. **Drift-check in CI** — CI detects staleness against code and reports/fails (a _check_), as opposed to silently auto-regenerating.

Every candidate fails **exactly one** conjunct. That single-conjunct failure is what keeps the claim alive.

## Closest near-misses (ranked)

1. **RepoAgent** — the strongest _mechanical_ "both." Generates a nested `Markdown_Docs/` tree + global-structure JSON, and its **pre-commit hook detects changed files (add/delete/modify) and auto-regenerates + commits** the affected docs. Fails the strict claim on two counts: (a) it _auto-updates_ rather than _drift-checks/fails_ — it never blocks on staleness, it silently rewrites; (b) it runs as a **git pre-commit hook, not CI**; (c) the docs are human-facing markdown, not an agent-facing router. If you relax "CI drift-check" → "keeps docs synced with code automatically," RepoAgent refutes.

2. **Loki Mode `loki docs`** (Autonomi) — the strongest _staleness-gate_ candidate. Generates `.loki/docs/` into the repo and ships **Gate 11 / documentation quality gate**: checks README existence and whether docs are **stale (>N commits, default 10, behind the code they describe)**, regenerating "once per run when docs are missing, and again only when >10 commits stale." This is a genuine committed-doc + staleness-check pairing in a build pipeline. Fails the strict claim because the docs are **human-facing** (docs generated _by_ the multi-agent SDLC framework, not an agent-facing AGENTS.md router) and the gate _auto-regenerates_ rather than failing to prompt a human fix. Hierarchy of `.loki/docs/` unconfirmed.

3. **hcc** (reyavir/hierarchical-context-compressor) — the strongest _architecture_ match: it is almost exactly the proposed framework (LLM picks which dirs get an `AGENTS.md`; root = concise TOC/router, nested = operational manuals; writes `agents.md` + per-dir `AGENTS.md` + `llms.txt`; optional commit via a `.github/workflows/` job). It is agent-facing, hierarchical, committed — and has a GitHub Actions path. It fails on **exactly one** conjunct: **no drift/staleness/verify mode at all** (confirmed generate-only from README). This is the single most important datapoint: the generation half of the claim is fully solved by an off-the-shelf tool; only the CI drift-check is missing, and hcc already runs in Actions, so bolting a `git diff --exit-code` after regeneration would close the gap in ~5 lines.

4. **agents-lint / context-drift** — the mirror image: mature **CI drift-checkers** for agent-facing files (stale paths, dead scripts, wrong dep versions, "context rot"), agent-facing by design — but they **only lint, never generate hierarchy**. The drift-check half of the claim is also fully solved off-the-shelf.

## Why the claim survives (the whitespace, precisely stated)

- **Both halves exist independently and maturely.** hcc = hierarchical agent-facing generation + commit. agents-lint/context-drift = CI drift-check of agent docs. No product fuses _these two specific halves_ into one tool.
- **The tools that fuse generate+check (RepoAgent, loki docs) do so for the wrong artifact** — human-facing docs — and they _auto-regenerate_ rather than _check-and-report_. The distinction matters for the framework: an agent-context router that silently rewrites itself on every commit is a different (and arguably worse, per Wave-1's "stale/wrong docs hurt") design than one whose staleness _fails CI and forces a curated human/agent update_.
- **The generic pattern is known but unpackaged.** "Regenerate on merge, `git diff --exit-code`, fail if output differs from checked-in" (angelkurten, Falconer living-docs guides) is a well-understood CI idiom. Nobody has shipped it wrapped around a hierarchical agent-facing generator. This is the exact whitespace the framework occupies.

**Confidence:** Moderate-high that no _packaged product_ refutes the strict claim as of 2026-07. Lower confidence that no _individual repo/CI config_ somewhere already does `hcc` + `git diff --exit-code` — that combination is trivial and may exist unadvertised; searches surfaced the ingredients but no assembled instance.

## Corroboration for Wave-1 threads (bonus, found en route)

- **ETH Zurich "LLM-generated context files hurt" — now with numbers (still secondary).** Search synthesis attributes to the ETH study: LLM-generated context files **reduced task success ~3% on average and raised inference cost >20%**, "auto-generated files perform worse than no file," while **human-curated files ≈ +4pp**. Consistent with Wave-1's +10-12pp/curated-helps, generated-hurts finding but different magnitudes — **primary source still not fetched; treat numbers as tertiary.** (Surfaced via augmentcode.com guide + search synthesis, not the paper.)
- **Practitioner convergence confirmed.** Multiple 2026 guides independently prescribe: root AGENTS.md = concise router/TOC + minimal overview; nested per-area files loaded on-demand ("right rules in the right place," "guide not encyclopedia"). hcc hard-codes this (8k chars/file, 40k/dir caps). Matches Wave-1's ≤200-line-root convention.
- **"Regeneratable artifact" framing is spreading** — guides now advise treating AGENTS.md as a _generated, versioned artifact fired on contract-change/weekly/manual, committed to a feature branch for review_ rather than a hand-maintained doc. This is adjacent to the framework's thesis and worth citing as ecosystem momentum.

## Why this file is not thin (and where it is)

It is **not** thin on the core question — the conjunctive matrix is fully populated with ~11 candidates and every near-miss is pinned to the exact conjunct it fails. It **is** thin in two spots: (a) Loki Mode's `.loki/docs/` **hierarchy** and its exact CI vs. internal-pipeline boundary are unconfirmed — the Autonomi web pages rendered as near-empty shells (SPA), so those cells rest on search-synthesis + the loki-mode README rather than primary docs; (b) I could not fetch the ETH primary source, so the +4pp/-3pp/>20% numbers remain tertiary. Neither gap changes the verdict: even granting Loki Mode its best case, it fails conjunct #2 (agent-facing), so the strict claim stands.
